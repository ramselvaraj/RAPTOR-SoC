RAPTOR-SoC SIMT GPU · Lesson 1

What are you building?

One tiny program. Hundreds of threads. Eight execution slots sharing a single instruction stream and one memory bus.

Before any SystemVerilog, get this picture in your head. Everything in simt_gpu/rtl exists to serve it.

1. The job: brighten an image

You have a 16×16 image = 256 pixels, packed one per 32-bit word. The source lives at word 0x2000, and you want the brightened copy at word 0x6000. The whole kernel is five instructions:

CONST r1, 0x20      ; delta = 32
LDR   r2, r14, r0   ; r2 = src[r0]      (r14 = SRC base)
ADD   r3, r2, r1    ; r3 = r2 + delta
STR   r3, r15, r0   ; dst[r0] = r3      (r15 = DST base)
RET                 ; done
Notice there is no loop. This program does not iterate over pixels. It is written as if it operates on one pixel. The r0 register — the thread index — is the only thing that decides which pixel. Run it once with r0=0 and you brighten pixel 0. Run it with r0=137 and you brighten pixel 137.

2. A thread is just that program plus private numbers

A thread is not a software process. Here it is nothing more than:

  • the same instruction text for everyone, and
  • its own copy of the 16 registers, and
  • one number that makes it unique: its thread index, parked in r0.

Because each thread owns its registers, r2 means "my pixel" to every thread simultaneously. That is the whole trick. One program, many private states.

3. Why not just loop on a CPU?

A CPU core does one thing at a time. To brighten 256 pixels it must run the fetch–decode–execute cycle 256 times, spending the expensive control logic (fetch, decode, program counter) on every single pixel. The arithmetic unit sits mostly idle.

A GPU makes a different bet: replicate the cheap stuff, share the expensive stuff. Copy the register file + ALU (the "data path") four times, but keep a single instruction fetch, single decoder, single program counter for all four. That shared bundle is a warp. Each replicated data path is a lane.

SIMT vs SIMD (the distinction that matters)

This looks like SIMD, but there is one crucial difference: each lane has its own register file and its own identity, whereas classic SIMD lanes have no state of their own. That is exactly why this is called SIMT — Single Instruction, Multiple Threads — and why the same program can be written per-pixel instead of per-vector. Lanes can also be switched off individually; that is the primitive this machine uses instead of branching.

4. The machine you actually have

Now map the words onto your specific design:

WordIn this machine
ThreadOne pixel's worth of state: 16 registers + an index in r0.
LaneOne physical data path: its slice of the register file plus an ALU.
Warp4 lanes that share one program counter and one instruction fetch.
Warps2 of them, so 8 execution slots (8 lanes) total.
KernelThe five instructions of brighten.
LaunchA start pulse carrying thread count + SRC/DST addresses.

5. What actually happens on a launch

  1. DCR sees start, latches the thread count and the SRC/DST addresses, and raises busy.
  2. Dispatcher turns the thread count into per-warp information: which lane indices are active, and what thread index each warp starts at.
  3. Scheduler looks at which warps are ready and grants exactly one the bus this cycle, rotating fairly.
  4. The granted warp fetches the next instruction over the shared bus and executes it in all four lanes at once.
  5. A load or store cannot move four words at once on a one-word bus, so the warp's mem_unit walks lanes 0…3 one at a time.
  6. RET halts a warp. When every warp has halted, DCR drops busy and pulses done.

6. Masking: the missing lanes

If the thread count is 6, warp 0 covers threads 0–3 (all four lanes on) and warp 1 covers only threads 4–5, so its lanes 2 and 3 are inactive. The dispatcher computes this as a lane mask. Inactive lanes still receive the instruction, but their writes to registers and memory are suppressed. This is the machine's only defence against out-of-range pixels.

7. Where you fit (Person A)

You own the left/top half of that diagram — the launch, the thread mapping, the arbitration, and the memory walk:
